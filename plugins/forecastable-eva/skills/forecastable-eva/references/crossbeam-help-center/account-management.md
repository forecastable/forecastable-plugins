You must be an Admin in Crossbeam to invite team members.

When inviting users from the team page with SSO enabled, the invitations will be sent directly to the team member.

Please note that invite reminders will be sent as follows:
- 3 days after the initial invite
- 4 days after the first reminder
- Weekly for one month
- Then monthly, for a total duration of 6 months
To invite Team Members to Crossbeam:
- Click the Settings gear in the bottom left to open Crossbeam Settings, then click Team
- Click the +Invite User button

- In the pop-up modal, select your Seat Type for the team member(s)--either a Full Access Seat (access to all Crossbeam products) or a Sales Seat (access to Crossbeam for Sales only)-- and enter the email address(es).

Next, select a Team Member role.

### Integration Seat
This is a dedicated seat type for connecting and managing data sources, CRM connections, and integrations. It is included with Supernode & Enterprise plans. It does not count towards your seat limit.

- Click Settings, then select Team
- Click the Invite User button
- In the invite modal, under Seat Type, select Integration
- Enter the user's email address and send the invite

The pending invite will appear in the My Team table. Once the user accepts, they'll be able to connect and manage data sources and integrations.

Convert an Existing User to an Integration Seat

- Click the Edit pencil icon in the user row

#### Enforcing SSO Log In
To enforce SSO log in, select Enable SAML SSO & Require SSO .


#### SSO Exception User
When OAuth (Open Authentication) is required from external applications, you will need to establish an SSO Exception User with Crossbeam to complete the integration. This also gives the option to exclude users from being required to log in via SSO. We recommend including anyone who cannot log in via SSO, or any additional users who can still access Crossbeam in the event of an identity provider failure
✍️ Note
Any existing users will be removed from Crossbeam unless you enter them into the SSO Login Exceptions box. They will need to login via Okta to be re-added to the account.


#### Pre-Provision SSO Users
SSO-enabled organizations can pre-provision users from the Invite user modal, located under the Setting Icon & click Team. If SSO is allowed, toggle on Pre-Register using SSO for SSO login. If SSO is required, the toggle will be set to on and unable to be adjusted.

Invited users retain their specified seats and roles when they log in via SSO.

Click Send invites when done.


#### Just-in-Time (JIT) Provisioning
New teammates can add themselves to this workspace if they have the appropriate IdP credentials. Every new user that gains access for the first time via SSO will be given the Seat Type user role set up during SSO.
✍️ Note
Select the drop down arrow in the Full Access Role box to make changes to default role. Learn more about user roles and permissions here .

Hit Save Settings to save your SSO configuration.

💡 Crossbeam Credits and Record Exports are separate limits. Credits are a meter to AI access to your ecosystem data balance only and have no impact on your Record Export limit. For more details, see Crossbeam Credits .

✍️ Note
The Free plan does not support record exports.
If your partner is on a Supernode or Enterprise plan, you'll automatically receive an Account Mapping Pass, allowing you to export up to 100 records.
Record Exports allow users to transfer enriched data from Crossbeam, gathered through account mapping activities, and transfer it to external platforms, such as data warehouses (e.g., Snowflake), integrations, and CRMs for further analysis.

Each record is counted once per subscription term, regardless of the number of integrations, destinations, partners, or overlaps. Even if a record undergoes multiple updates within that subscription term, it still counts only once.
✍️ Note
The Record Exports permission is enabled by default for users. If you want to restrict record exports, you'll need to manually change this setting to No Access by editing the Record Export permission in Crossbeam.
Learn more in Managing User Seats and Roles in Crossbeam .

#### Estimated Exports in Integration Settings
From the Integration workspace, open the integration settings to see an estimated number of Record Exports. These estimates are designed to help users understand the potential impact on their Record Exports before finalizing the data push options in your settings.

How Estimates Are Calculated:
- The estimate is based on the number of matches found The estimated number does not reflect the exact number of unique records that will be exported when settings are saved
- The estimated number does not reflect the exact number of unique records that will be exported when settings are saved
As a result, the estimated export count is often higher than the actual number of records deducted from the user’s export limit.
✍️ Note
Slack Integration, all Crossbeam Copilots, Crossbeam for Sales are excluded from the Record Export limits.

#### Record Exports and Net New Accounts
- The New Accounts for You List contains Net New Account records that will count towards record export limits
- Records on New Accounts for Your Partner List will not count towards limits because these are records that already exist in an org's data source

#### CSV file and Google Sheets
- Adding a new CSV and/or Google sheet data, will be counted as new records
- Updating and/or deleting current CSV or Google Sheet data will not count as new records
- If you delete a CSV or Google Sheet and later upload the same CSV or Google Sheet, this will count as a new CSV or Google sheet data, and will be counted as new records
